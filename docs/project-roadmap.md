# Project Roadmap — Anjali Diagnostics LIS

This document describes future phases. **Nothing below is implemented yet** unless explicitly marked. Each phase will be developed, reviewed and approved incrementally.

Legend: ✅ done &nbsp; 🔜 planned (not implemented)

## Phase 0 — Project Initialization ✅
- Monorepo structure (`frontend/`, `backend/`, `docs/`), Git, `.gitignore`, env examples.

## Phase 1 — Authentication + Dashboard ✅
- Login (`/login`), protected dashboard (`/dashboard`), header, collapsible sidebar, stat/action cards, Today's Bills & Today's Due Bills (demo data).
- Backend: Express + Mongoose, User model, bcrypt + JWT in an HTTP-only cookie, `auth` + demo `dashboard` endpoints.

- ✅ **2.1 Foundation**: Patient model + Counter + minimal AuditLog; concurrency-safe Patient ID generation (`GP202600001`); `POST/GET /api/v1/patients`, `GET/PUT /api/v1/patients/:id` with search + pagination; `/patients` list, `/patients/new` form, `/patients/[id]` profile with inline edit; sidebar Patients nav enabled; demo seed (`npm run seed:patients`).

- ✅ **2.3 Lab navigation + Cancel Lab Bill + Collect Lab Dues**: sidebar restructured (Patients item removed; lab features grouped under **LABORATORY → LAB BILL** and **LABORATORY → TEST RESULT**, with coming-soon placeholders); `LabBill` cancellation fields + `LabBillPayment` model; endpoints `GET /lab-bills/due`, `GET /lab-bills/by-bill-number/:billNumber`, `POST /lab-bills/:id/cancel`, `POST /lab-bills/:id/collect-due`; `requirePermission` middleware (admin/staff cancel+collect, operator view+create); pages `/laboratory/billing/cancel` and `/laboratory/billing/collect-dues`; dashboard Due Collection card wired; OSP bill view shows cancelled badge/banner; proxy guards `/laboratory`.
- ✅ **2.4 Lab billing UI sheets + Modify + Vendor-Client**: replicated sheet layouts for **Cancel Lab Bill** (inline `Enter Bill Number :` search + always-visible 9-column bill table, cancellation remarks, `Cancel Bill / Clear / Home`), **Collect Lab Dues → Investigations Collect Dues** (radio filter `To days Dues / Criteria / Bill No`, 8-column dues table with `No Records To Display` + `Total` footer, secondary `Name/Amount/Bill Date` items table, LEFT Payment Mode / MIDDLE Comments / RIGHT Total–Enter Discount(Rs.)–Net–Paying block, `Submit / Clear / Home`; additional per-collection `discountAmount` stored on `LabBillPayment`, discount validated against outstanding and payable recomputed server-side, net/due totals updated); **Modify Lab Bill** (`/laboratory/billing/modify`: top-right Search + fullscreen toggle, selectable bill list with Ref Id/Pat Id/Pat Name/Gender/Age/Mobile/Pat Type, three-panel Departments / Lab Tests (`>>` transfer) / Existed Lab Tests with qty & delete, Payment Mode + comments + `Display comments in Bill` checkbox, right-side Total / Enter Discount : % / Discount ₹ / Net / Paid / Balance, `Submit / Clear / Home`; new `PUT /lab-bills/:id` via `billing.modify` permission — bills are re-snapshotted + re-priced server-side, cancelled and already-paid bills rejected, audit entry `lab_bill.modified`); **Vendor-Client Lab Bill** (`/laboratory/billing/vendor-client` reusing the OSP structure with a database-driven **Client picker**, `billType: "vendor"`, `VCB2026XXXXX` bill numbers, client required + inactive rejected). Backend additions: `LabClient` model + `/api/v1/lab-clients` (search/list/create/update, `VC<YYYY>XXXXX` codes, seeded demo clients), `LabBill.billType` + `clientId/clientName`, shared FE components (`BillPageHeader`, `BillActionBar`, `ClientPicker`); sidebar Modify/Vendor-Client now wired; `TEST RESULT` sub-modules remain placeholders.
- 🔜 Patient documents & attachments, patient history/timeline, patient-facing dashboard widgets, duplicate detection on registration.

## Phase 2.5 — Lab Sample Collections + Parameter Based Test Results + Lab Reprint ✅
- **Sample Collections** (`/laboratory/test-result/sample-collections`): **Lab Sample Collection Status** sheet with status legend (🟩 Collected / 🟪 Received / 🟦 Processed / 🟨 Recollected / 🟥 Rejected / Not updated), `Today Lab Bills` / `Criteria` (bill date range + bill no + patient id/name) filter, and the 12-column table `S.No | Bill No | Bill Date | Patient Id | Patient Name | Department | Test Name | Test Status | Sample Status | Time | Comments | Action` with per-row status dropdown + time + comments + Save; rows tinted by status. Backend `GET /lab-samples` (mode=today|criteria, lazy `SMP<YYYY><6-digit>` sample creation per bill+test from `LabTest.sampleType/containerType`, derived `testStatus` OPEN/CLOSED) and `PATCH /lab-samples/:id/status` enforcing the allowed transition map (SELECT→[COLLECTED,REJECTED], COLLECTED→[RECEIVED,RECOLLECTED,REJECTED], RECEIVED→[PROCESSED,RECOLLECTED,REJECTED], PROCESSED→[RECOLLECTED], RECOLLECTED→[RECEIVED,REJECTED], REJECTED→[COLLECTED]) with per-timestamp fields (`collectedAt/receivedAt/processedAt/recollectedAt/rejectedAt`), history entries, optional HH:MM time, and 422 on illegal jumps.
- **Parameter Based Test Results** (`/laboratory/test-result/parameter-based-test-results`): **Enter Test Result** sheet — selectable bill list (`Bill No | Pat Id | Pat Name | Sex/Age | Bill Date`), radio today/criteria + **☑ Include Client Bills**, tests table (`Print | Dept Name | Test Name | Sample | Out | Lab Center`) with print checkboxes + CLOSED indicator, **Select Signature to print** technician dropdown, and the parameter table (`Order | Parameter Name | Result | Units | Reference Range | Method`) with type-aware inputs (TEXT / NUMBER|RANGE / BOOLEAN / SELECT); existing results pre-filled; `Submit / Clear / Home`. Backend `POST /lab-test-results/results/submit` upserts per (billId,testId,parameterId), first write = version 1, later writes push the previous document into `revisions` and bump `version` (no silent overwrite), validates result types + that the test belongs to the bill + bill is `generated`.
- **Lab Reprint** (`/laboratory/test-result/lab-reprint`): bill list + its tests, signature selector, `Submit / Clear / Home / Print / Send Mail / Send Whatsapp` (Mail/WhatsApp are safe demo placeholders; Print opens `window.print()` of a dedicated print-only report preview while the UI is `print:hidden`).
- Backend additions: `LabSample`, `LabTestParameter`, `LabTestResult`, `LabTechnician` models; `updateSampleStatusSchema` + `submitResultsSchema` validations (TIME_24H_REGEX); `lab-technicians` endpoint; `listLabBills` gained `fromDate`/`toDate`/`billType` filters; seed catalog extended with demo parameters (CBC/Lipid/FBS/LFT/etc.) + demo technicians (`npm run seed:lab`). Permissions: admin/staff get `sample.view/update`, `test_results.view/enter/update`, `reports.print`; operator remains view-only for samples/results (403 on PATCH/submit).

## Phase 3 — Reports (REPORTS module) ✅
- Sidebar **REPORTS** category with 11 items: **Generated Lab Bills**, Lab Summary Report, OSP Patient Registration Report, Referral Doctor Commission, Lab Collection Summary, Client Lab Generated Bills, Outside Sent LabTest Details, Dues, Cancelled Bills, Bill-wise Collection, Hospital Price Card.
- ✅ **Generated Lab Bills** (`/reports/generated-lab-bills`, `GET /reports/generated-lab-bills`): OSP billing history view (generated + cancelled; cancelled rows marked `CANCELLED` and excluded from totals). Filters: Bill Date From/To, Patient ID, Patient Name, Bill Number, Patient Type, Department, Referring Doctor, Payment Status (derived from `paidAmount`/`dueAmount`). Server-side pagination + projection; MongoDB aggregation computes totals (Bills / Amount / Discount / Net / Paid / Due) over the filtered `status: "generated"` subset. Values come from bill item **price snapshots** only. Legacy pre-`billType` OSP bills remain visible (missing `billType` ≈ OSP; `vendor` excluded). Index added on `LabBill.items.departmentId`. Permissions: `authenticate` + `requirePermission` (`reports.view` + `reports.generated_bills`, admin/staff only — operator 403).
- ✅ **Lab Summary Report** (`/reports/lab-summary`, `GET /reports/lab-summary`): OSP tests grouped by department with group headers/totals. Filters: date range, comma-separated `departmentIds`/`testIds`, `patientTypes` (gp/op/ip/er), bill number, derived `labStatus` (OPEN/CLOSED), `approvalStatus` (PENDING/APPROVED), `delayedTat=1`. **Lab/Approval status is derived** (CLOSED/APPROVED = results entered for that bill+test; documented via `meta.labStatusBasis`/`approvalStatusBasis`); **Delayed** = report date ≥ 24 h (`DELAYED_TAT_HOURS`) after bill date without results. Totals: bills + amount.
- ✅ **OSP Patient Registration Report** (`/reports/osp-registration`, `GET /reports/osp-registration`): patient registrations by date range with `gender`/`mobile`/`name`/`billType` filters. Printed sheet header renders as **GP Patients Report**. Totals: patients/bills + bill amount.
- ✅ **Referral Doctor Commission** (`/reports/referral-doctor-commission`, `GET /reports/referral-doctor-commission`): per-bill commission rows filtered by `doctorIds`/`departmentIds`/`testIds`/`patientId`/`patientTypes`, with `commissionBasis = referral (OSP bills only) | cons_op_ip (OP+IP bills only)` and `amountBasis = net | paid`. Rate resolution order **test → department → doctor default**; a missing rate is flagged (`configMissing`) and shown *missing*, never silently 0%. Claim Type currently only supports `all`. Printed sheet title **Lab - Dr Referral - Bill wise**.
- ✅ **Lab Collection Summary** (`/reports/lab-collection-summary`, `GET /reports/lab-collection-summary`): lab income vs expenses by date range. **Expenses are 0** surfaced via `meta.expensesUnavailable` + a displayed note (no expense module yet). Printed sheet title **Lab Income And Expense**.
- ✅ **Client Lab Generated Bills** (`/reports/client-generated-lab-bills`, `GET /reports/client-generated-lab-bills`): **vendor** bills separated from OSP billing; filters `clientIds`, `referringDoctorId`, `orderBy = date_asc | date_desc`. Totals: bills + total/discount/net/paid/due.
- ✅ **Outside Sent LabTest Details** (`/reports/outside-sent-lab-tests`, `GET /reports/outside-sent-lab-tests` + `GET /reports/outside-labs` for filter options): tests whose samples were marked **sent out** to an outside lab (`LabSample.outsideLabId`/`sentOutAt`), filtered by date range + `outsideLabIds`. Row Total Amount = the **originating bill-item charge snapshot**.
- ✅ *Shared report infrastructure*: `utils/report-core.ts` — `dayRange()` inclusive from/exclusive to+1 day (`{$gte,$lt}`), CSV multi-value params (`departmentIds=ID1,ID2`), `slicePage()` pagination, and `export=1` full-result export capped at `EXPORT_LIMIT=1000` (print/CSV carry the whole filtered result, ignoring page/limit). Frontend shared components (`ReportToolbar` with Find/next-match + row highlighting + Refresh, `ReportFilterBar` with Show/Clear/Home actions, `ReportSelectionPanel`, `ReportTable` with blue header + totals footer, `ReportSummary`, `ReportPagination`, `ReportDateRange`/`ReportSearchInput`/`ReportSelect`, `ReportPrintSheet` print-only sheet, `report-export.ts` BOM-prefixed CSV downloads) reused by all 11 report pages; each page is proxy-guarded and supports **Print** (browser dialog) + **Export** (CSV). All values from bill **price snapshots** only. Plus `GET /reports/options` (`reports.view`) supplying shared filter options (bill types, pay modes, active users, price-card dropdowns).
- ✅ **Dues** (`/reports/due-bills`, `GET /reports/due-bills`): generated bills with `dueAmount > 0` filtered by date range + patient ID + Collected By (searchable multi-select of active users). "Collected By" = the latest payment's collector name from `LabBillPayment`. Summary + totals row: Bills / Amount / Discount / Net / Paid / Balance. Permissions `reports.dues` (admin/staff; operator 403).
- ✅ **Cancelled Bills** (`/reports/cancelled-bills`, `GET /reports/cancelled-bills`): cancellation history with **Summary / Detailed** mode toggle; filters date range + Bill Type + Pay Mode + Cancelled By multi-selects. Summary shows short bill list; Detailed adds Bill Type + test names; remarks shown. Totals row: Bills / Net. Cancellation from `LabBill.cancelledAt/cancelledBy/cancellationRemarks`. Permissions `reports.cancelled_bills`.
- ✅ **Bill-wise Collection** (`/reports/bills-wise-collection`, `GET /reports/bills-wise-collection`): per-payment ledger from `LabBillPayment` (one row per payment event). Filters: date range, Patient ID, Sort Order, Patient Type (GP/OP/IP/ER checkboxes), With Cancelled Bills, and Bill Type / Collected By / Pay Mode multi-selects. Columns Cash / UPI / Card / Bank Transfer / Other breakdown (from `PAYMENT_MODES`, no invented modes); cancelled bills excluded unless `withCancelled=1`. Summary + totals row per mode. Permissions `reports.bill_collection`.
- ✅ **Hospital Price Card** (`/reports/hospital-price-card`, `GET /reports/hospital-price-card`): lab test price list for hospital charges. Filters Service Type (default `lab-test`), Select Department, Select Lab Name (main lab "Anjali Diagnostics" — backend has no org module yet), Status (Active/Inactive/All). OP Amt = `LabTest.price`; IP / Ins IP / ER / Ins ER have no tariff source yet and render `—` with a `meta.tariffsUnavailable` note (no fabricated tariffs). Totals: test count. Permission `reports.price_card` (added to admin/staff).
- 🔜 **Hospital Price Card IP/ER tariffs** — separate IP/ER/insurance price fields per test (requires a price-card tariff module) so the IP / Ins IP / ER / Ins ER columns show real values instead of `—`.

## Phase 4.1 — Database (LIS master data) modules ✅
- Sidebar **DATABASE** category with **DOCTOR** (Create Doctor, Doctor Specialisation, Doctor Designation) and **COMMON** (New Address, New Department, Create Package) groups, proxy-guarded (`/database`).
- **Create Doctor** (`/database/doctor/create`): full-registration form (Doctor Type, Employee ID, First/Middle/Last Name, Short Name, Gender, Qualification, contacts, Specialisation/Designation/Department, Online App. Display, Room Number, OP/IP/Hospital/ER fees, Max Free Visits / Days). `name` computed server-side from name parts; legacy billing quick-create still accepted; `/doctors/list` paginated with edit + activate/deactivate (referenced doctors locked via `DoctorCommission`/`LabBill`).
- **Doctor Specialisation** / **Doctor Designation**: case-insensitive-unique masters (shared `MasterContent` screen), edit + activate/deactivate (referenced records locked via `Doctor`).
- **New Address** (`/database/address/new`): cascading Country → State → District → City selects + inline "Add new" inputs; Save creates only the missing chain levels with auto-parenting; full-chain address table with edit-rename and activate/deactivate.
- **New Department** (`/database/department/new`): Type dropdown (`Lab & X-Ray`, Service, Doctors, Pharmacy, Stores, Inventory, CRM), Name, Short Name, Sort Order, Description; list with search/status filter/edit + activate/deactivate (referenced departments locked via `LabTest`).
- **Create Package** (`/database/package/create`): three-panel layout (Package Details: Name/Type `Lab`/Amount/Amount In; Select Tests: Department → Test → Add; Selected Tests list); package table `S.No | Package Name | Package Type | Amount | Ins Amount | Edit`; edit loads the full saved package. Names intentionally **not unique** (dup `VITAMIN PROFILE` rows seeded via stable `seedKey`); `FEVER PROFILE` = exactly 6 seeded tests.
- Backend: `database-options`, `doctor-specialisations`, `doctor-designations`, `locations` (hierarchical, parent-level validated), `packages` modules + extended `doctors`/`departments`; `backend/src/constants/master-data.ts`; permissions `database.view` + `database.{doctor,specialisation,designation,location,department,package}.{read,write}` (admin/staff; operator 403). Idempotent seed `npm run seed:db` (7 specialisations, 5 designations, 10 locations, 4 departments, 6 fever tests, 14 packages).
- Frontend shared database components: `PageHeader`, `FormField`, `FormSection`, `FormActions`, `DataTable`, `SearchInput`, `StatusBadge`, `ConfirmDialog`.
- 🔜 Department Type filters per screen, package tariff/billing integration (billing a package as a group of tests), client-side smart-add in the address cascade, doctor photo/signature upload (Phase 10).
